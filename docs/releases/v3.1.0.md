# bla-agents v3.1.0 — Agent-First Closed-Loop Hardening & Crown-Jewel Entanglement

**Date:** 2026-11-07 (America/Los_Angeles)

## Headline

Minor release upgrading BLA 3.0 into a strict **Agent-First Closed-Loop Hardening Engine**: adds Check 7 (`crown-jewel-entanglement`) and syntax validation (`syntaxValid`) to `bla_verify_weave`, extends structural weave verification to native `.c`/`.cpp`/`.cc`/`.rs`/`.go` sources (`verifyNativeWeaveFile`), wires `require_agent_weave` (`--require-agent-weave`) into both `bla_harden` and `bla_defend`, and ships the 6-round Red-Blue adversarial weave validation suite.

## Added

- **Check 7 (`crown-jewel-entanglement`) & `syntaxValid` in `bla_verify_weave`:** rejects cosmetic side-effect-only weaves, raw boolean gate returns (`return true`/`return false`), cleartext secret equality comparisons, hardcoded `FLAG{...}` literals, lane-independent byte oracles, and broken syntax introduced during Stage 2 source surgery.
- **Native Source Weave Verification (`verifyNativeWeaveFile`):** `bla_verify_weave` / `bla verify-weave` now verifies `.c`, `.cpp`, `.cc`, `.rs`, and `.go` sources against all 7 `WEAVE_ACCEPTANCE_TESTS` checks.
- **Agent-First Pre-Flight Gate (`require_agent_weave` / `--require-agent-weave`):** supported on both `bla_harden` (`hardenProject`) and `bla_defend` (`defendTarget`), returning `agentWeaveAssessment` (`surgicalWorkorders` + `agentActions`) and refusing mechanical hardening when source files have not yet passed `bla_verify_weave`.
- **Crown-Jewel Candidates & Data-Flow Entanglement Plan (`bla_weave_plan`):** extracts `crownJewelCandidates` and `dataFlowEntanglementPlan` across JS/TS, Python, and C/Rust/Go targets.
- **Red-Blue Adversarial Suite (`tests/red-blue-v3-adversarial.test.ts`):** Rounds A–F proving resistance against write-only state decoys, dead-branch calls, local shadowing, per-byte lane oracles, and sibling sidecar tampering.
