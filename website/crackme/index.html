CrackMe v6 — harden-native challenge

The public target is literally bla harden output: a small multi-format app (Node vault + HTML panel + WebAssembly core) hardened at bankrupt intensity.

Why v6

v5.x was a hand-written crypto sponge. The harden-native edition runs hardenProject() — the same pipeline as bla harden <dir> --intensity bankrupt — over a real app tree, with risky LLM directive layers OFF. The cleartext template is public; the challenge is recovering the per-build constants and logic from the hardened output.

Stages

  • Stage A — 16 key-byte lanes sealed through the hardened core.wasm
  • Stage B — the hardened panel.html derives an entitlement token
  • Stage C — the key decrypts the flag; one uniform DENIED

Run

npm run crackme:v6 -- '<16-char-key>'

Submit a solve

Hash the FLAG with SHA-256 and open a GitHub issue using the CrackMe v6 solve template. The hash must match flagSha256 in challenge/v6/SEAL.json (plaintext key and FLAG are not in git).

Honest scope

BLA raises cost for automated AI reverse-engineering agents and plants decoys. It does not claim immunity to patient interactive human reverse engineering.
